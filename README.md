# 射箭計數（ArcheryCounter）— Wear OS

作者：**ZGrCc**

戴在手腕上，自動偵測每次放箭並計數；偵測到時手錶會震動一下，也可以用 − / + 手動修正。
每次偵測都會自動存成一筆「記錄」，並分析每一箭放箭前**手臂的穩定度**，方便你比較每次射擊之間的差異。

目前版本：**v1.8**。

### v1.6
每個新功能都有設定開關。
- **自動暫停**（預設關）：偵測中超過 N 分鐘（5～30，預設 10）沒有放箭，就自動暫停並長震一次，主畫面顯示「已自動暫停」。校準錄製不適用。休息比較久的話請調長。
- **低電量提醒**（預設開）：偵測中電量低於 15% 時長震一次，主畫面顯示「電量低」。只提醒，不會自己動作；充電或回到 20% 以上後才會再提醒。
- **今日目標箭數**（預設 0 = 關閉）：設定頁用 −/+ 設目標（每次 10，最多 300）。主畫面顯示「今日 36 / 120」，是今天所有記錄的箭數合計（含進行中的這一次，不含誤判與校準）；達標時長震一次。
- **每趟結束回饋**（預設開，需要「分趟統計」）：滿一趟時主畫面顯示約 5 秒，內容是這一趟的平均晃動量，以及比上一趟、比本次平均「較穩」或「較抖」多少%（差不到 3% 算「差不多」）。第一趟沒有可比較的對象。
- **偵測中降低亮度**（預設關）：偵測中把螢幕亮度降到低 20%／中 40%／高 60%，暫停後恢復。部分手錶可能不理會這個設定。
- **恢復預設設定**：設定頁最底部，一鍵還原所有設定項（含目前的距離、弓種條件），要再確認一次。不動記錄、主畫面的箭數和閾值。
- **關於**：設定頁最底部顯示版本號與記錄資料夾在手錶上的路徑。
- 震動優先順序：達標 > 滿趟 > 一般放箭，同一箭只震最重要的那一種，不疊加。
- 版本號升到 1.6（versionCode 7）。

### v1.5
- **固定簽章，更新時不用先卸載**：設定好 GitHub Secrets 之後，每次編譯出來的 APK 簽章都一樣，可以直接 `adb install -r` 覆蓋安裝，記錄和設定都會保留。做法見下方〈固定簽章〉。沒設定 Secrets 時仍照舊（每次簽章不同，要先卸載）。
- **閾值建議**（設定頁「偵測」區塊）：用你標記過的「誤判」和「有效」的峰值，算出較合適的閾值並可一鍵套用。至少要有效 10 筆、誤判 3 筆。**只能建議調高**（減少誤判）；漏判看不出來。校準錄製不參與。
- **條件標籤**（預設開）：設定頁選「距離」（室內18米／室外30米／50米／70米／其他）和「弓種」（反曲／複合／其他），新記錄自動帶上；詳情頁可以事後修改。記錄列表會顯示標籤；跨次趨勢頁可切換「只看相同條件」（以最新一次記錄的條件為準）。
- **偵測中觸控鎖**（預設開）：偵測中主畫面有「鎖定觸控」按鈕，鎖定後只顯示箭數，**長按螢幕約 2 秒**才解鎖，避免拉弓、放箭時誤碰「−」或「暫停」。只擋螢幕觸碰，擋不住實體按鍵。
- **校準錄製**（設定頁 → 校準錄製）：引導依序錄「只拉弓不放箭」「正常射擊」「取箭走動」三段，每一段按「開始」和「結束」，起止時間標注在記錄裡，並強制錄原始資料。校準期間偵測照常運作、放箭也會記錄，但不計入主畫面箭數；這筆記錄標為「校準」，不計入跨次趨勢和閾值建議。把 `sessions` 資料夾交給 Claude 就能依你的實際資料調整參數。
- **儲存空間管理**（設定頁「資料」區塊）：顯示記錄、原始資料、匯出檔各占多少空間；可「只刪除原始資料」（再確認一次），記錄本身保留，進行中的那一筆不動。
- 版本號升到 1.5（versionCode 6）。

### v1.4
每個新功能都有對應的設定開關（詳見〈設定頁〉），不想用的都可以關掉。
- **記錄頁管理模式**：按「管理」後，每筆記錄前面出現 ☐ / ☑，可以勾選多筆、全選，再按「刪除已選 N 筆」（會再確認一次）。進行中的記錄不能選。不用長按，也不用滑到詳情頁最底。
- **分趟統計**（預設開）：詳情頁新增「逐趟」區塊（每趟的箭數、時間、平均晃動量、放箭後晃動量、環數合計）。每趟箭數預設 6，可設 1～12；兩箭間隔超過 60 秒也算新的一趟。分趟是從現有資料算出來的，舊記錄也有。
- **滿趟震動**：滿一趟時震動節奏和平常不同。每一箭只輕震一下（約 0.06 秒）；滿趟那一箭只震滿趟的節奏，可選「三連震」（預設）、「兩短一長」、「一次長震」或「關閉」。手錶的震動馬達多半不能調頻率，所以用節奏區分。
- **放箭後跟隨動作**（預設開）：每箭多記放箭後 1 秒的波形，並算出「放箭後晃動量」（放箭後 0.3～1 秒，避開放箭衝擊本身），用來看放箭後持弓手臂是穩住還是甩開。只對新記錄有效；放箭後 1 秒內就暫停偵測的那一箭沒有這項（顯示「—」）。
- **跨次趨勢**（預設開）：記錄列表每筆顯示平均晃動量；新增「跨次趨勢」頁，畫最近 20 次的平均晃動量（由舊到新）。
- **每箭環數輸入**（預設關）：開啟後，在單箭頁用 − / + 輸入 0～10 環。詳情頁顯示平均環數；有輸入環數的箭達 8 箭以上時，會算晃動量和環數的相關係數（箭數少，僅供參考）。
- **匯出摘要**：設定頁按鈕，產生 `summary.csv`（每次記錄一行）和 `shots.csv`（每箭一行），放在 `sessions` 資料夾，一次 `adb pull` 就能取出。
- **靜止條件與冷卻時間可調**：設定頁的「偵測」區塊，靜止條件預設 5（2～10），冷卻預設 3 秒（1～6）。立即生效。
- 設定頁依用途分組：一般、偵測、記錄、分趟、圖表、資料。
- 版本號升到 1.4（versionCode 5）。

## 取得 APK（用 GitHub 雲端編譯，不需要安裝 Android Studio）

1. 登入 GitHub，新建一個倉庫（Private 即可）。
2. 把本資料夾裡的所有檔案（**包含隱藏的 `.github` 資料夾**）上傳到倉庫。
   - 網頁上沒有「新增資料夾」按鈕：點 **Add file → Create new file**，檔名欄輸入路徑（例如 `.github/workflows/build.yml`），輸入 `/` 就會自動建立資料夾，再把內容貼進去。
3. 打開倉庫的 **Actions** 頁面，等 `Build APK` 跑完（約 3～5 分鐘，綠色勾表示成功）。
   - 沒有自動開始的話，點左邊的 Build APK，再點右邊的 Run workflow。
4. 點進該次執行，在頁面最底部的 **Artifacts** 下載 `ArcheryCounter-apk`，解壓縮後有兩個檔案：
   - `app-release.apk`：開啟較快，**建議使用這個**。
   - `app-debug.apk`：備用。
5. 如果出現紅色叉叉（編譯失敗），點進去把紅色的錯誤訊息複製下來，貼給 Claude 協助修正。

## 安裝到手錶（adb）

手錶和電腦要連同一個 Wi-Fi。

**一、手錶開啟開發者選項**
1. 設定 → 系統 → 關於 → 版本，連點「版本號碼」7 次。
2. 回到設定，進入「開發者選項」，開啟 **ADB 偵錯** 與 **無線偵錯**。
3. 進入「無線偵錯」，記下 **IP 位址與連接埠**（記作 A），再點「配對新裝置」，記下 **配對碼** 與另一組 **IP:連接埠**（記作 B）。

**二、電腦準備 adb**
下載 Google 的 Android SDK Platform-Tools（只有 adb 等小工具，不是 Android Studio），解壓縮，並把 APK 放進同一個資料夾。

**三、配對、連線、安裝**（Windows 的 PowerShell 要在 `adb` 前面加 `.\`）
```
adb pair <B 的 IP:連接埠>          # 依提示輸入配對碼
adb connect <A 的 IP:連接埠>
adb install app-release.apk
```
看到 `Success` 就完成了。無線偵錯每次重新開啟，連接埠都會改變，要重新看手錶上的數字。

**⚠ 更新版本前是否要先解除安裝，取決於簽章**
- **已設定固定簽章**（見下方〈固定簽章〉）：直接覆蓋安裝，記錄和設定都保留。
  ```
  adb install -r app-release.apk
  ```
- **沒有設定固定簽章**：每次 GitHub 編譯出來的 APK 簽章都不同，直接覆蓋安裝會失敗（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）。要先執行：
  ```
  adb uninstall com.example.archerycounter
  ```
  這會清除計數、設定和**手錶上的所有記錄**。如果有想保留的記錄，**先用下面〈取出資料〉的方法備份到電腦**。
- **第一次換成固定簽章時**，因為簽章和之前的不同，**還是要最後一次** `adb uninstall`（先備份記錄）。之後就不用了。

## 固定簽章（只要設定一次）

1. 到你的 GitHub 倉庫：**Settings → Secrets and variables → Actions → New repository secret**。
2. 依序新增四個 Secret（名稱要完全一樣）：`KEYSTORE_BASE64`、`KEYSTORE_PASSWORD`、`KEY_ALIAS`、`KEY_PASSWORD`。值在 Claude 另外給你的 `ArcheryCounter-signing-secrets.txt`（或你自己產生的金鑰）裡。`KEYSTORE_BASE64` 是很長的一整行，整串貼上，前後不要有空白或換行。
3. 把本專案推上去（或在 Actions 頁面手動 Run workflow）。編譯記錄的 **Prepare signing key** 步驟會顯示「使用固定簽章金鑰」就代表生效。
4. 這個金鑰檔**不要放進倉庫**（專案的 `.gitignore` 已經排除 `*.jks` 和 `ArcheryCounter-signing-secrets.txt`）。弄丟的話，重新產生一把、更新四個 Secret，並再做最後一次卸載重裝。

自己產生金鑰（需要電腦裝有 Java 的 `keytool`）：
```
keytool -genkeypair -keystore release.jks -storetype PKCS12 -alias archery -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 release.jks      # 輸出的整串就是 KEYSTORE_BASE64（Windows 可用 certutil -encode）
```
這把金鑰只適合自己使用的 App，不適合上架。

## 使用方式

### 主畫面
- **箭數**：目前累計的箭數。累計數會一直保留，直到你按「歸零」。
  - **+**：手動加 1（漏判時用）。
  - **−**：若本次記錄中有還沒取消的偵測，就取消最近一筆（標為誤判，資料保留、不列入統計）；沒有的話才是手動 −1。
- **開始偵測 / 暫停偵測**：開始一次記錄／結束這次記錄。
- **歸零**：只在暫停時出現，避免射箭時誤觸。
- **閾值**：多大的衝擊算一次放箭。數值越大越不靈敏。漏計就調低；誤計（拉弓、取箭時被算進去）就調高。
- **上次峰值**與**晃動量**：最近一箭的衝擊強度，以及放箭前的加速度晃動量與角速度晃動量。
- **記錄**、**設定**：進入對應頁面。往右滑動可返回上一頁。

- 名詞：**最終箭數 = 偵測箭數（不含誤判）+ 手動加減**。記錄裡的箭數每次從 0 算起，和主畫面累計的「箭數」互不影響。

## 穩定度怎麼算

你的手錶戴在持弓手，所以放箭前持弓手的抖動，反映的就是瞄準階段手臂穩不穩。

每偵測到一箭，就取放箭前的一段時間窗口（預設 2 秒，並避開最後 0.1 秒的放箭衝擊），計算：

> 晃動量 = √( 平均( |樣本 − 窗口平均值|² ) )

- **加速度晃動量**：單位 m/s²，用的是已扣除重力的線性加速度。
- **角速度晃動量**：單位 °/s，來自陀螺儀。手錶沒有陀螺儀時只記加速度，介面會顯示「此手錶沒有陀螺儀」。
- 先扣掉窗口平均值，是為了去掉緩慢、持續的移動，只留下抖動的成分。
- 窗口內樣本少於 10 筆時，該箭的晃動量顯示「—」。

**怎麼看這些數字**
- 數字越小越穩。沒有「好」或「壞」的標準值，只能和你自己的其他箭、其他次訓練比較。
- 這量的是**手腕的抖動**，不是準星實際的晃動，也不知道箭的落點，不能直接和成績畫等號。
- 拉弓過程中持弓手本來就會移動。如果你的瞄準時間比視窗短，視窗會包含一部分拉弓動作，數字會偏大。可以把視窗改成 1 秒，或把原始資料交給 Claude 分析後決定。

## 取出資料（給 Claude 分析）

所有記錄都存在手錶上這個位置：

```
/sdcard/Android/data/com.example.archerycounter/files/sessions/
```

用 adb 一次拉到電腦（先照上面〈安裝到手錶〉的步驟連線）：
```
adb pull /sdcard/Android/data/com.example.archerycounter/files/sessions ./sessions
```
然後把 `sessions` 資料夾裡的檔案上傳給 Claude 即可。

### 檔案內容
每筆記錄用開始時間命名，例如 `20261019_211003`：
- `20261019_211003.json`：記錄本身（每次記錄都有）。
- `20261019_211003.csv`：原始資料（只有開啟「錄製原始資料」時才有）。

**匯出的 CSV**（設定頁按「匯出摘要」後，與記錄放在同一個 `sessions` 資料夾）：
- `summary.csv`：每次記錄一行。欄位 `id, start, duration_s, detected, cancelled, manual_plus, manual_minus, final_count, threshold_min, threshold_max, peak_avg, interval_avg_s, accel_rms_avg, gyro_rms_avg, follow_accel_avg, follow_gyro_avg, scored, score_avg, tags, calibration`（多個標籤以 `|` 分隔）。
- `shots.csv`：每一箭一行。欄位 `session, no, time, rel_ms, peak, threshold, accel_rms, gyro_rms, follow_accel_rms, follow_gyro_rms, score, cancelled`。誤判的箭 `no` 留空、`cancelled` 為 1。沒有的數值留空。

**檔案大小**：JSON 很小，每箭約 0.2 KB，加上單箭波形每箭再多約 0.5～1 KB。真正會讓檔案變大的只有 CSV：約 100 Hz 取樣，**每 30 分鐘約 10 MB 以上**。不需要原始資料時請關閉「錄製原始資料」。

**CSV 欄位**（約 100 Hz，每行一筆）

| 欄位 | 說明 |
| --- | --- |
| `t_ms` | 距這次記錄開始的毫秒數 |
| `ax, ay, az` | 線性加速度（已扣除重力），m/s² |
| `a_mag` | 加速度合力大小，m/s² |
| `gx, gy, gz` | 角速度，°/s（和最近一筆加速度配對；沒有陀螺儀時為 0） |

**JSON 結構**
```
id, startMs, endMs（-1 表示沒有正常結束）, threshold, windowSec, hasGyro, rawCsv
tags:  ["室外70米", "反曲"]                      條件標籤，沒有設定就不會出現
cal:   true                                      校準錄製才有
marks: [{ l, s, e }, ...]                        校準的各段動作：l = 名稱，s/e = 起訖毫秒（同 rel）
shots:  [{ rel, peak, thr, acc, gyr, x, wf, fa, fg, sc }, ...]   rel = 距開始的毫秒數；acc/gyr 可能缺漏
        fa/fg = 放箭後 0.3～1 秒的加速度／角速度晃動量；sc = 環數（0～10）；都只有在有資料時才會出現
        x:1 = 已取消（誤判），沒有就是有效
        wf = { s: 取樣間隔毫秒, i: 放箭位置的索引, a: [加速度合力], g: [角速度合力] }，只有開啟單箭波形才有
manual: [{ rel, d }, ...]                     d = 實際加減的數量（+1 或 −1）
```
`rel` 和 CSV 的 `t_ms` 使用同一個時間基準，可以直接對齊，在波形上標出每一箭的位置。

### 建議的錄法
1. 在設定頁開啟「錄製原始資料」。
2. 分幾次記錄來錄：**只拉弓不放箭**、**正常射擊**、**取箭走動**，各錄一段，我就能看出各種動作的波形差別。
3. 射完告訴 Claude 每次記錄實際射了幾箭，用來對照應用判定的次數，找出漏計或誤計。

## 已知限制與尚未驗證的部分

- **手錶端程式（畫面、感測器、檔案存取、唤醒鎖）撰寫時無法在雲端環境編譯，也沒有在實機上測過。**
  純邏輯（放箭偵測、穩定度計算、統計、記錄檔的存取、波形取樣、誤判取消、分趟、環數相關性、匯出、震動節奏、標籤、閾值建議、校準標注、占用空間、自動暫停、低電量、今日目標、每趟回饋）有跑過測試，全部通過。
  第一次編譯如果失敗，請把 GitHub Actions 的錯誤訊息貼給 Claude。
- 「保持亮屏」只能保持螢幕不因逾時休眠。用手掌蓋住螢幕、按實體按鍵等系統強制熄屏的情況擋不住；
  「CPU 喚醒鎖」只能讓 CPU 繼續運作，不能保證所有手錶在熄屏後感測器都繼續送資料。
- 螢幕一直亮著加上唤醒鎖會明顯耗電，長時間訓練前請先充滿電。陀螺儀也會增加耗電。
- 記錄頁的「刪除」放在詳情頁最底部（不是長按）。
- 偵測的靜止條件（前 0.5 秒合力 < 5 m/s²）、冷卻時間（3 秒）目前仍是預估值，尚未用你的實際資料校準；
  只有「放箭閾值」是你實測調過的。
- 圖表是用 Canvas 自行繪製，在圓形螢幕上的邊緣裁切與字體大小尚未實機確認。
- 感測器事件時間戳與系統時間基準是否一致，尚未實機驗證；若單箭波形的放箭豎線位置明顯不對，請告訴 Claude。
- 手錶的震動馬達多半不能調「頻率」，滿趟與放箭的區別是靠節奏（長短與次數）。實際感覺要實機試過，不滿意可在設定換樣式。
- 「放箭後晃動量」是放箭後 0.3～1 秒內相對於該段平均值的抖動，反映手臂放箭後動得多大，不是動作好壞的判定。這段的取樣在放箭後 1 秒才完成，期間應用若被系統中斷則該箭沒有這項。
- 環數和晃動量的相關係數只在有輸入環數的箭達 8 箭以上才會顯示，樣本少時容易受偶然影響。
- 「瞄準階段分析」（自動分出拉弓、固定、放箭）尚未實作，等有原始資料後再設計。
- 固定簽章依賴 GitHub Secrets 與 workflow 設定，我在雲端環境無法真的跑一次 GitHub Actions，所以第一次編譯請看 **Prepare signing key** 步驟有沒有顯示「使用固定簽章金鑰」。
- 觸控鎖的「長按 2 秒」是自訂的手勢偵測，實機的手感（太長或太短）要試過才知道。
- 電量提醒用系統的電量廣播，自動暫停、亮度、今日箭數的即時更新都只在實機上才能確認，雲端環境無法測試。
- 「每趟結束回饋」比的是「本次記錄的平均」，不是「今天所有記錄的平均」。
- 手錶的主畫面有 Tile（磚）可以快速開始偵測，這一版沒有做，因為要加額外套件、出錯會讓整個編譯失敗；等 v1.7 確認能用再考慮。
- 「瞄準階段分析」（自動分出拉弓、固定、放箭）仍未實作，要先用校準錄製取得你的原始資料。
- 啟動動畫、圖示、簽章指紋的讀取，都是 Android 畫面或系統程式碼，雲端環境無法編譯與預覽；動畫只用 Compose 內建功能，沒有新增套件。圖示在手錶桌面上實際長什麼樣、動畫順不順、點按手感如何，要裝上手錶才知道。
